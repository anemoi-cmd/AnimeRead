# 小说朗读与声音训练路线

这是下一阶段的设计和训练教程，0.9.5 尚未实现小说朗读，也不附带声音模型。旧章节总结、朗读、生图的占位接口已删除。

## 先选路线

小说需要 TTS：文字 → 语音。建议先用 [GPT-SoVITS](https://github.com/RVC-Boss/GPT-SoVITS) 验证授权声线的日语及中文朗读；其官方提供短录音参考、少量数据微调和多语言推理。先试参考音频是否已够用，再决定是否微调。

[RVC](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI) 是声音转换：已有语音 → 另一种音色。它本身不读取小说文字，需要先经过 TTS，再转换一次，延迟和维护成本更高。[Fish Speech](https://github.com/fishaudio/fish-speech) 也提供 TTS，但目前代码与权重使用自己的研究许可；保留商业发布选择时，应逐项确认所选代码、基础权重及数据许可。

东山奈央等真人声优的名字不能当作随意发布的官方身份标识。计划公开下载其声线前，先确认本人／事务所与录音权利方允许训练及分发。实际试跑建议使用自己的声音或明确授权的配音；基础模型开源许可不能代替这些授权。

## 一次完整的小规模训练

1. 在阅读器工程之外安装官方 GPT-SoVITS Windows 环境，固定所用发布版本与基础模型。不要把训练工具、Python 环境和数据集放进 AnimeRead 仓库。
2. 准备同一个人的干净语音。先用几分钟检查流程，再根据试听质量增加；作为工程试验建议准备 30–60 分钟自然朗读，不是质量保证或硬性最低要求。保留原始 WAV，只在副本上清理背景音乐、重叠人声、混响、削波与长静音。分离工具不能把糟糕素材变成可靠的录音。
3. 按句子切为约 3–10 秒片段，这是便于校对的起始范围；使用官方 WebUI 的切分工具。统一录音格式，按所选模型版本要求重采样，不自行把所有版本当成同一种采样率。
4. 为每段制作准确字幕。日语可用官方集成的 Faster-Whisper 生成初稿，然后逐条人工听写校正名字、假名、数字与标点。字幕必须与声音一致，删掉读错或缺字的片段。
5. 预留约 10% 的不同句子和一段长文用于验证，不参加训练。按所选版本 WebUI 顺序完成文本／语音特征、训练集整理和微调。先用默认参数少量跑通；不同版本的 GPT、SoVITS 或 LoRA 步骤有差异，不把旧双模型教程直接套到新版本。
6. 比较基础模型、参考音频推理与微调后结果。用同一组未见句子检查漏字、重复、停顿、专名读音、情绪和一分钟以上的长文。过多轮次可能过拟合；以验证试听选择检查点，而不是只看训练损失。
7. 导出推理必需的声线权重／适配器、基础模型版本、参考音频及其准确字幕、语言和许可证。声线权重不能独立朗读，还需要相匹配的引擎与共享基础模型。

原生中文朗读和把中文翻译成日语是两个功能。日语录音训练出的音色不保证中文发音准确；先验证跨语言效果，再决定是否加入授权中文数据。不要为追求音色相似而省去读音、漏字和长文验证。

## 接入 AnimeRead 的顺序

先在独立环境中完成一条句子的本地推理，再接入实际章节文本：按标点分句、生成当前句、预生成下一句、顺序播放。播放和翻页互不阻塞；停止、换书或跳章时取消旧任务。后续加入暂停／继续、语速、句子定位和断点续读，再做声线下载管理。

推理进程与阅读器隔离，通过本机接口交换文本、任务编号、采样率和音频；只监听回环地址，允许取消，设置超时和队列上限。先做一个真实可用的 TTS 后端；章节总结和生图等功能等确定使用场景后再实现，不恢复万能空接口。

## 模型按需分发

源码仓库只放模型目录和说明，每项记录声音名称、模型／基础引擎版本、语言、大小、SHA-256、下载地址、许可证和授权说明。模型权重放独立 GitHub Releases，用户勾选后才下载；共享基础模型下载一次，声线权重各自下载，支持删除与缓存上限。建议让用户选择 D 盘等模型目录。

GitHub 普通 Git 文件超过 100 MiB 会被阻止；[官方建议](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)使用 Releases 等渠道分发大文件。[Release 单个文件需小于 2 GiB](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)，较大的基础模型应按引擎认可的文件边界拆包或使用其官方模型托管。不要把每次训练检查点都提交进 Git 历史。

下载先写临时文件，校验摘要后再安装，失败清理临时数据。权重格式优先选安全的张量格式；需要 PyTorch 检查点时使用引擎支持的受限加载方式，不把任意下载文件当成可执行脚本。公开目录中不包含训练原始录音、未经授权的声线或访问密钥。
